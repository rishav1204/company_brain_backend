# ERP-side AI capabilities inventory (migration source of truth)
# ================================================================
# STATUS: MIGRATION COMPLETE (Waves 0, A–G).
#   erp/**/ai/** no longer exists. Every capability below now lives in
#   finance_os (invoice_ai / forecasting / domain_intelligence/<domain>)
#   and is reached from ERP only through the typed ports in
#   erp/ports/intelligence_registry.py, registered by
#   finance_os/bridges/erp_command_bridge/bootstrap.py.
#   HTTP paths and response shapes are unchanged.
#   Enforced by app/modules/architecture_fitness/test_erp_ai_migration_fitness.py.
#   The rows below are kept as the capability → new-owner map.
#
# Purpose (original): plan move of intelligence from ERP → Finance OS without
# losing functionality. Every row was implemented under
# modules/erp (except where noted as already FOS-backed).
#
# How to use for migration:
#   1. Treat each "Capability ID" as a moveable unit.
#   2. Preserve Inputs → Outputs contract (especially API response shapes).
#   3. Leave ERP only: write side effects (create invoice/claim/journal) via
#      command bridge; domain validators (GSTIN, fiscal) can stay in ERP.
#   4. "Stay in ERP?" = likely domain rule, not true FOS brain work
#      (optional fold later; not priority).
#
# Implementation style (realistic):
#   Most ERP ai/* are rule/heuristic/score engines, NOT LLM services.
#   FOS already has richer AI (invoice pipeline, agents, runtime).
#   Move = relocate logic + register port + rewire ERP call sites.
#   Capability must stay equivalent (same flags, scores, rankings).
#
# External deps often used by ERP AI (not FOS):
#   - platform.documents.ai.ledger_suggester (AP invoice + journals)
#   - erp match engines / repositories / validators
#
# Already FOS-backed (partial dual path — migrate remaining ERP local):
#   InvoiceIntelligencePort — extraction/dup/anomaly/predictions/confidence
#   ForecastIntelligencePort — reporting forecast series
