# Audience: YOU as platform owner / ops / SRE / ML platform — NOT:
#   - end users (CFO, accountant, AP clerk)
#   - customer-company "tenant_admin" / org.admin of a paying org
#
# Contrast with _wave0_api_by_owner.txt:
#   That file groups by code package owner (module ownership).
#   This file groups by human operator surface (control plane).

# Reality check (important):
#   Cross-tenant staff surface is gated by platform.admin (sections 4A + 5),
#   held only by the platform_owner role. Hard ops still use
#   ops.worker.manage / ops.queue.manage. Several observability routes only
#   require a valid JWT + org (build_request_context) and still scope audit/org
#   fields to the caller's org. Treat "intent" separately from "hardened".

# settings.api_prefix (see main.py). OpenAPI remains source of truth.

## 4A) Cross-tenant operator console (REAL platform admin)
# The only routes in this file that see past a single org. Gated by
# PLAT_A = require_permission("platform.admin"), which permission_guard gives
# no tenant_admin fallback, so a customer-company admin gets 403 (verified).
# Held only by the platform_owner role (migrations 086 + 087).

METHOD  PATH                                              GUARD     SOURCE
------  ----                                              -----     ------
GET     /ops/platform/orgs                                PLAT_A    modules/platform/operator/routes/operator_routes.py
GET     /ops/platform/users                               PLAT_A    modules/platform/operator/routes/operator_routes.py
GET     /ops/platform/usage                               PLAT_A    modules/platform/operator/routes/operator_routes.py
POST    /ops/platform/users/{user_id}/status              PLAT_A    modules/platform/operator/routes/operator_routes.py
POST    /ops/platform/users/{user_id}/sessions/revoke-all PLAT_A    modules/platform/operator/routes/operator_routes.py

# /orgs   — every tenant with plan, status, active/total user counts.
# /users  — users across all orgs (filters: org_id, status, search), with roles
#           and live session counts. Backs the "see all users" dashboard.
# /usage  — per-org rollup over ?days=N: billing.ai_usage (requests/tokens/cost),
#           platform.api_request_log (api calls), billing.usage_metrics.
# /status — the block button: active | suspended | deactivated in ANY org.
#           Suspending also revokes live sessions, so access stops immediately
#           instead of at token expiry. Refuses to act on the caller (no
#           self-lockout).
# /sessions/revoke-all — force logout in any org without changing status.
#
# Mutations resolve the target user's org from the DB, then delegate to the
# ordinary org-scoped IAM repositories, and are audited into the TARGET tenant's
# audit log with actor_type=platform_operator and cross_org=true.
#
# CAVEAT — these cross-org reads issue no set_rls_org, because there is no single
# org to pin the GUC to. That works only while the app's DB role is not subject
# to RLS (today the Neon owner has BYPASSRLS, so every CREATE POLICY in the
# migrations is inert for app traffic — tenant isolation is currently enforced by
# the WHERE org_id clauses in the repositories, not by Postgres). If the app ever
# moves to a least-privilege role, these queries go quiet rather than erroring.

## Permissions you care about as platform ops
# Seed / assign these to staff principals (not customer CFOs):

  ops.worker.manage   — run workers, worker webhook consume
  ops.queue.manage    — enqueue/process, DLQ requeue, event replay

# Both permission keys were absent from core.permissions until migration
# 086_platform_owner_role.sql, so require_permission() could not pass for any
# principal. That migration adds them and creates the role:
#
#   platform_owner   — every key in core.permissions incl. the two ops.* above.
#                      Deliberately NOT granted to tenant_admin, which is a
#                      customer-company admin role.
#                      Seeded onto a login by backend/scripts/seed_platform_owner.py,
#                      which also assigns tenant_admin for the role-name gates
#                      (_require_tenant_admin, require_agent_read).
#   Section 1 additionally needs ENABLE_WORKER_ROUTES=true.

  platform.admin      — cross-tenant operator console (section 4A) AND commercial
                        control plane (section 5: plan assign, credit grant,
                        entitlement override). Added by migration 087, granted
                        to platform_owner only. Never add it to
                        _TENANT_ADMIN_ALLOWED in permission_guard.py: that would
                        hand every customer admin a cross-tenant console.

# Delivered by sections 4A + 5:
    — cross-org user directory, block/unblock, forced logout
    — AI cost + API call volume per org (/ops/platform/usage), which was the
      "AI gateway cost across all orgs" gap; /ai/analytics stays per-org
    — multi-tenant billing grants (plan/credits/entitlements) on platform.admin

# Still missing (recommended later):
    — global infra metrics without borrowing a customer org (/metrics is
      per-org)
    — training promotion without borrowing a tenant JWT (section 4)
    — ERP↔FOS intelligence port health (see GAP note in section 2)
    — a dedicated platform org for operator principals: platform_owner
