## 1. Platform layers

| Layer | Role | Source of truth |
|-------|------|-----------------|
| **ERP (M6–M24)** | Accounting, procurement, inventory, tax, banking | PostgreSQL `erp.*` |
| **Platform (M1–M5, M34–M37)** | IAM, workflows, events, policy, billing | `core.*`, `platform.*` |
| **Finance OS intelligence (M25–M33)** | Invoice AI, memory, graph, agents, analytics | `finance_os.*` |
| **M38 Platform AI Runtime** | Goal planner, execution graph, observe/continue loop | `finance_os.goals`, `goal_runs`, `execution_graphs` |

**Golden rule:** AI may read, draft, recommend, and launch workflows. It must **never** auto-post journals, execute bank payments, or file GST without human approval and workflow gates.

---

## 2. Request lifecycle (UI → audit)

```text
Browser / API client
  → IAM (JWT, org context, RLS)
  → M34 PolicyEngine (mutations)
  → Domain service (erp.* / finance_os.*)
  → PostgreSQL + audit log
  → M3 Event bus (async consumers)
  → M27 Memory / M28 Graph / M33 Audit / M38 GoalManager
```

Every mutation emits domain events. Consumers are idempotent and org-scoped via RLS.

---

## 3. M38 runtime lifecycle

```text
User chat / ERP event / scheduler
  → GoalManager
  → GoalPlanner (NL → DAG + plan metadata)
  → ExecutionGraph persisted
  → while not complete:
        next_ready_node
        if requires_approval and not approved: pause
        Executor → ToolRegistry → domain service
        Observer → success | retry | alternatives | fail
        SelfCorrection / RollbackManager (on failure)
  → M33 audit + M37 billing gate
```

See [`DATA_FLOWS/09_agent_execution.md`](DATA_FLOWS/09_agent_execution.md) and [`DATA_FLOWS/10_multi_module_goal.md`](DATA_FLOWS/10_multi_module_goal.md).

## 6. Tool catalog map (M38 Phase 2 target)

Tools are `{domain}.{method}` — not agents. Initial set (~20) in `platform_ai_runtime/tools/erp_tools.py`:

| Domain | Read | Draft / workflow |
|--------|------|------------------|
| procurement | list_pos, get_po | create_po, submit_po, create_grn, confirm_grn, cancel_po |
| inventory | list_balances, list_items | create_item, receive |
| ap | list_invoices | create_invoice_draft, submit_for_approval |
| ar | list_overdue | — |
| treasury | get_cash_position | — |
| workflow | — | start |
| memory / graph | search, traverse | — |

Target: 100+ tools mirroring every UI action (Phase 2 — **156 tools registered**).

Phase 2 layout:

| Package | Role |
|---------|------|
| `tools/catalog_read.py` | 119 read tools (list/get/search) |
| `tools/catalog_draft.py` | 33 draft/submit/workflow tools |
| `tools/tool_spec.py` | Declarative `ToolSpec` + adapter handler factory |
| `tools/erp_tools.py` | Custom handlers (confirm_grn, receive, etc.) |

Each catalog tool carries `policy_action` and draft tools declare `compensation` where applicable. Forbidden tool names (`journal`, `payment`, `gst`) are avoided — use `journals`, `tax_gst`, `ap.propose_payment_schedule` instead.

## 7. Approval tiers

| Tier | Examples | Gate |
|------|----------|------|
| **Read** | list_*, get_*, search | Policy read |
| **Draft** | create_*, draft_* | Human approval in M38 graph |
| **Workflow** | submit_for_approval, start workflow | M2 maker-checker |
| **Forbidden** | journal.post, payment.execute, gst.file | Hard block (`forbidden_actions.py`) |
